# Entitlements (Free / Pro)

> Loaded when you work under `Shared/Entitlements/`. The strategy (what will be Pro, price, sequencing, App Review risks) is in `docs/superpowers/specs/2026-09-30-entitlements-foundation-design.md`. The root file's cross-cutting rules (Swift 6, `@Observable` without `didSet`, xcodegen, tests) still apply. Lines tagged **RULE** override default behavior.

## What is here (2026-09-30: a FOUNDATION, nothing is locked)

- `EntitlementState` (`.free` / `.pro(EntitlementSource)`), `EntitlementPolicy.resolve` (pure: local purchase → `.pro(.purchase)`, else iCloud record → `.pro(.cloudMirror)`, else — DEBUG only — « Simuler Pro » → `.pro(.debugOverride)`, else `.free`).
- `CloudEntitlementRecord` — the purchase proof, `version` 1, JSON; `decode(_:)` returns `nil` for an unknown version or a malformed blob, never traps. Carries the StoreKit JWS (`signedTransaction`) for a future verifying reader.
- `CloudKeyValueStore` (injectable protocol) + `UbiquitousCloudKeyValueStore` (`NSUbiquitousKeyValueStore.default`, listens to `didChangeExternallyNotification`); `CloudEntitlementMirror` keeps ONE record under the KVS key **`entitlement.pro.v1`**.
- `EntitlementStore` — `@MainActor @Observable`, process singleton `AppNavigation.sharedEntitlements`, injected via `.environment`. Mutators `refresh()` (launch + every `scenePhase == .active`), `recordPurchase(_:)` (local `SettingsKey.entitlementLocalRecord` + mirror), `clearLocal()`, `setDebugOverride(_:)` (`#if DEBUG`, `SettingsKey.debugSimulatePro`). Its Debug reader is Settings → Debug (`EntitlementDebugRows` on iOS, inline on tvOS).
- **Early adopters** (2026-10-01): `EarlyAdopterPolicy.swift` (pure — `BuildNumber`, `AppTransactionSnapshot`, `EarlyAdopterConfiguration.production`, `EarlyAdopterStatus`, the DEBUG `EarlyAdopterDebugOverride`, the Keychain payload `EarlyAdopterCacheRecord` v1) + `EarlyAdopterService` (`@MainActor @Observable`, process singleton `AppNavigation.sharedEarlyAdopter`, injected via `.environment`; publishes `isEarlyAdopter`). Source = `AppTransaction.shared` behind `AppTransactionSource` (`.unverified` throws, never trusted); cache = the app-private Keychain item `early_adopter` behind `EarlyAdopterCache`. `refreshIfNeeded(isOnline:)` asks StoreKit once per process as soon as the network allows; `evaluate()` always asks (a user tap). A failed fetch keeps the cached status. **Either app counts**: each publishes its verified PRODUCTION facts (`EarlyAdopterCacheRecord`, JWS included) to the shared iCloud KVS under its own key `earlyAdopter.ios.v1` / `earlyAdopter.tvos.v1`, reads the OTHER key (at init, on `refreshIfNeeded`, on every `didChangeExternallyNotification`) into `otherPlatformStatus`, and `isEarlyAdopter` = own status OR the other's. Nothing grants on `isEarlyAdopter` yet — it is to be plugged into `EntitlementStore`. Settings → Debug shows it (« Early adopter » row).
- **The Pro purchase (lot 2, 2026-10-12 — spec `docs/superpowers/specs/2026-10-12-pro-purchase-design.md`)**: `ProProduct.swift` (product ids `com.cinemax.ios.pro` / `com.cinemax.tvos.pro` — one non-consumable per app, Family Sharing, created by hand in App Store Connect; `ProductSnapshot`, `ProEntitlementFact`, the outcomes, and the pure `ProPurchasePolicy.reconcile`), `ProStore.swift` (`ProStoreClient` protocol + `StoreKitProClient`, the StoreKit 2 adapter; `ProStore`, `@MainActor @Observable`, process singleton `AppNavigation.sharedProStore`, injected via `.environment`, `start()` in the root `.task`, `refresh()` on every `.active`), `ProFeatureCatalogue.swift` (the eight features the Pro page sells, each with `isGated`). UI in `Shared/Screens/Pro/` (`ProScreen`, `ProTierViews` — `ProTierLook`, the logo decoration, `ProTierChip`, `ProTierInks` / `ProTierMaterial` / `ProTierEmblem`, `ProMembershipCard` —, `ProPurchaseBlock`, `ProUpsellSheet`, `ProLockedFeatureRow`). The material is ONE quiet recipe (the founder's, recette 2026-10-13): a near-black ground carrying the tier's colour (gold, the accent, neutral graphite for free), brushed hairlines, a faint corner light, the colour itself kept for the metallic name and the emblem — tokens `CinemaColor.titaniumDeep`/`titaniumPlain`, `founderGold*`, `metalLight`/`metalShade` (mixed into the accent with `Color.mix`), all fixed materials in both modes. The iPhone / iPad card (design C, 2026-10-14) wears it with a 1 pt edge in the tier's colour and no coloured shadow — a neutral one in light mode only; the brighter « titanium » card of design A read as a muddy grey and a wall of yellow. **The material and its inks are ONE source (`ProTierMaterial` + `ProTierInks`)**, worn by the card and, edge to edge, by the **Apple TV page (design D « Immersif », 2026-10-13)**: no card there — `SettingsScreen`'s tvOS background swaps its accent bloom for the material while `selectedCategory == .pro` (shaded at the foot), the tier's name is the headline, the actions follow, and the features are a row of capsule pills (`pro.feature.*.short`) whose focused one is spelt out on the line above. Being dark in both modes, the tvOS page reads its tokens in the dark scheme (`.environment(\.colorScheme, .dark)`), and the detail's back button takes `onTitanium` there. Local StoreKit: `Tests/CinemaxKitTests/Fixtures/JellyGlassPro.storekit`, wired as both schemes' `storeKitConfiguration` (runs from Xcode only — `simctl` launches and archives ignore it, so a CLI-launched simulator reads « Prix indisponible », by design).
- `import StoreKit`: `EarlyAdopterService.swift` and `ProStore.swift` only.
- **`ProFeatureGate` (2026-10-12) — THE « may this user use a Pro feature? »**, first reader: multi-account (`AppState.multiAccountProvider` → `keepsAccountSessions`: Pro keeps every remembered account signed in, free lists them but each switch is a sign-in — spec 2026-10-20, see `docs/rules/server-setup-and-multi-server.md`). `EntitlementStore.proTier(earlyAdopter:)` → `.free` / `.pro` / `.founder`. **RULE — before the Pro launches (`EarlyAdopterConfiguration.production` has no pivot) EVERYBODY passes, as a founder**: the founder recognition only works on a verified PRODUCTION transaction, so `isPro || isEarlyAdopter` would lock the feature on the simulator, TestFlight and every Debug build until 3.0. Setting the pivot is what ends the free period. DEBUG « Palier simulé » (`proTierOverride`, `debug.proTier`) forces a tier, or `.launched` (real state as if the Pro had launched).

## RULEs

- **RULE — playback is never paid.** No playback path (the player, `PlayLink`, `CardActionPresenter`, resume, next-up, subtitles/audio pickers, SyncPlay JOIN) may ever read `EntitlementStore`. Joining a Watch Together session stays free; only creating one is a Pro candidate. A gate on playback is a product regression, not a feature.
- **RULE — the KVS identifier `$(TeamIdentifierPrefix)com.cinemax.shared` is the SAME in `iOS/Cinemax.entitlements` and `tvOS/CinemaxTV.entitlements` (both generated from `project.yml`) and must never diverge nor be renamed.** Identical identifiers are what make the two apps (different bundle ids, so no universal purchase) read one store; renaming it silently strands every mirrored purchase in the old container. It is NOT in the widget or the Top Shelf. Signing needs the iCloud capability on both App IDs — automatic signing adds it with `-allowProvisioningUpdates`; CI builds unsigned and cannot see a missing one.
- **RULE — in a DEBUG build, no `AppTransaction` outside a path the USER explicitly triggered** (a « Restaurer » / « Acheter » tap, the « Early adopter » Debug row in Release). In a Debug build it raises a sandbox Apple-account prompt; at launch that is a prompt nobody asked for. Hence the early-adopter launch evaluation (`AppNavigation`'s `onChange(of: network.isOnline, initial: true)`) is wrapped in `#if !DEBUG`: measured 2026-10-01 on the iOS 27 simulator with a Release build: exactly ONE `AppTransactionQuery` at launch, answered `noAccount` (Sandbox, no account signed in) with NO dialog, the failure logged and the cache kept; the Debug launch issued none. TestFlight / production on a device are NOT yet verified — check on the first TestFlight build that carries this; a Debug build runs on the Keychain cache + the override. Only `AppTransaction.shared` — never `AppTransaction.refresh()`, which prompts everywhere.
- **RULE — the early-adopter build pivot compares `CFBundleVersion` (the BUILD, `CURRENT_PROJECT_VERSION`), never the marketing version, and as dotted NUMBERS (`BuildNumber`)** — this project's builds are `1`, `1.0.2`, `2.3.2`, so text compare (`"1.0.10" < "1.0.2"`) and `Int(_:)` are both wrong. Each app has its own `originalAppVersion` (different bundle ids). Sandbox / TestFlight report « 1.0 », Xcode's local StoreKit the CURRENT build (measured 2026-10-01: `2.3.2`, `.xcode`) — all three are `.nonProduction`, never an early adopter; only the DEBUG override forces a status there. Local StoreKit cannot fake an old `originalAppVersion` (no knob in `SKTestSession` nor the `.storekit` file), so the production branch is only provable through the policy tests.
- **RULE — `EarlyAdopterConfiguration.production.pivotBuild` is set to the FIRST Pro build in the very release that ships the Pro.** Both pivots `nil` means « the Pro has not launched », i.e. every production install is an early adopter — true today, and the failure mode of forgetting is « Pro for everyone », never « the founders lose it ». Both pivots set = EITHER grants. The cache keeps the transaction's FACTS (`AppTransactionSnapshot`), never a verdict, so a pivot change re-decides every user, offline ones included; a verified answer replaces the cache both ways (the facts are immutable, only the configuration moves).
- **RULE — an Apple account that got EITHER app before the Pro is an early adopter on BOTH** (product decision 2026-10-01). The apps have different bundle ids, so each has its own `AppTransaction`; the bridge is the iCloud KVS. **One key PER platform, never a shared one**: a TV app installed after the Pro would otherwise overwrite the iPhone's proof with its own « regular » facts. Only production facts are published (a TestFlight answer would overwrite the tester's own App Store record). Limits, by construction: both devices must share the iCloud account (KVS) — not only the App Store account — and the early app must have run ONCE with this code and a network to publish; until then the other app reads `.unknown` and flips live on the external change. One build pivot serves both apps because `CURRENT_PROJECT_VERSION` is shared in `project.yml`; if the two ever diverge, the pivot must become per-platform. The mirrored record is trusted like `entitlement.pro.v1` (user-writable in principle); `signedTransaction` is there for a verifying reader.
- **RULE — the iCloud mirror is a cross-platform CONVENIENCE, never the truth on the platform the purchase was made on.** There, the truth will be StoreKit (`Transaction.currentEntitlements`); the mirror only lets the OTHER app unlock. `clearLocal()` leaves the mirror alone (it may be the other platform's record). The KVS is user-writable in principle (1 MB, no server check) — `signedTransaction` exists so a later reader can verify the JWS rather than trust the blob.
- **RULE — the record's wire format is a contract between two binaries of possibly different versions**: add a field only as an optional; anything else bumps `version` (and, if old readers must keep working, moves to a new KVS key `entitlement.pro.v2`). Dates use the coder's default strategy in both apps.
- **RULE — a TestFlight preview of the purchase is a COMPILE-TIME switch, `PRO_PREVIEW`, never a runtime test of the environment.** `ProFeatureGate.proLaunched` answers `true` under `#if PRO_PREVIEW`, passed only on the archive's command line (`SWIFT_ACTIVE_COMPILATION_CONDITIONS='$(inherited) PRO_PREVIEW'`). App Review runs in the same sandbox as TestFlight (`AppTransaction.environment == .sandbox` for both, same receipt), so « sandbox ⇒ launched » would put a paywall in front of the reviewer of every 2.x release, for a feature production users get free, with an in-app purchase not yet submitted. **A preview build is never submitted for review.** A preview build also recognises NO founder (`ProFeatureGate.recognisesFounders`): with no pivot every production install is an early adopter, and the tester's own Apple TV (or an earlier App Store install) publishes that to their iCloud — the preview opened on « Fondateur » with no purchase button. After the pivot, a TestFlight tester's own facts are non-production, but **a tester whose other platform published production founder facts IS a founder on the RC too** (the bridge works both ways): testing the purchase on the 3.0 RC needs a device on another iCloud account. A preview build ALSO carries the « Palier simulé » row (`#if DEBUG || PRO_PREVIEW` — the tester switches founder / Pro / free / launched on the device; « Simuler Pro » stays DEBUG-only). DEBUG « Palier simulé » gains `.launched` (real state, as if launched) — the one that walks free → purchase → Pro on the local StoreKit file.
- **RULE — on the platform the purchase was made on, `Transaction.currentEntitlements` is the truth, and the records follow it** (`ProPurchasePolicy.reconcile`, at launch, on `.active`, on every `Transaction.updates` element, after a purchase or a restore): decisions are taken on POSITIVE evidence only (`ProEntitlementState`). A verified, non-revoked entitlement (bought or family-shared) ⇒ `recordPurchase` when the local record or OUR mirror is missing or stale (the other platform's mirror record is left alone — it serves just as well, and rewriting it would churn iCloud on every launch of both apps). A PROVEN revocation (`Transaction.latest` carries a `revocationDate`) ⇒ `revokeOwnPurchase`, which removes the local record AND the mirror when its `writerBundleID` is ours — even with no local record left (refunded, deleted, reinstalled) — re-reading the key just before (the other platform may have rewritten it). A mere ABSENCE (App Store signed out, a restored device not synced yet, an iPad on another App Store account) ⇒ `clearLocal()` only: the other platform must not lose its Pro over that; accepted cost, a signed-out device stays Pro through its own mirror. **A test purchase (sandbox, TestFlight, Xcode — `CloudEntitlementRecord.environment`, an OPTIONAL field) is recorded locally but never mirrored, and a reader ignores one found in iCloud**: the key-value store has no test / production split, so a tester's sandbox purchase would otherwise unlock their production Apple TV for good. **A refresh drops an answer overtaken by a newer one** (`ProStore.generation`): a read started before a purchase must not revoke it on its way back (`staleRefreshCannotUndoPurchase`, verified RED without the guard). **The result alert is held by `ProStore.lastOutcome`, shown by `proPurchaseResultAlert` on a container that survives the tier flip** (the Pro page, the contextual sheet — one host at a time), and the account screens no longer swap on the tier (one list for both tiers since 2026-10-20), so a purchase made from the « Avec Pro… » hint of a reconnection flips `keepsAccountSessions` without tearing that sheet or « Merci ! » down — the reason the two presenters used to freeze their tier is gone with them. `currentEntitlements` is StoreKit's local cache: it answers offline, so the launch never blocks on the network. Only VERIFIED transactions count, each is `finish()`ed; `AppStore.sync()` only on the « Restaurer les achats » tap (it may ask for the Apple-account password). Measured 2026-10-12 on the iOS 27 simulator, Debug build, no StoreKit file: `start()` at launch raised no account prompt. A refund reaches the entitlement cache asynchronously (`ProStoreKitTests` polls the reconcile).
- **RULE — Réglages shows the tier (« Votre niveau »: logo ring + medal + chip, opening the Pro page whose head is the membership card `ProMembershipCard`) only when `ProFeatureGate.showsProEntry` (launched, `PRO_PREVIEW`, or a Debug « Palier simulé » other than automatic).** Product decision 2026-10-12: shown to EVERY user from the launch, never before. Before the launch, production users never see a Pro page — nothing is on sale yet, and App Review would meet a product it cannot buy. The free-tier PRO entry (`ProLockedFeatureRow` in the iOS switcher's free content and in Settings' plain `UserSwitchSheet`) only exists for a FREE tier, which itself only exists once launched.
- **RULE — the Pro page never sells a feature that is still free (`ProFeatureCatalogue`, spec R8).** Each listed feature carries `isGated`; only the remembered accounts are gated today. `ProFeatureCatalogueTests` fails if the production pivot is set while a listed feature is still free — lot 3 gates the others, each with its founder audit, BEFORE the pivot.
- **RULE — never shown at launch, never re-offered on its own, never on a playback path** (spec R9): the Pro page is reached from Réglages, the contextual sheet only from a tap on an entry marked PRO.
- **RULE — Release ignores « Simuler Pro »**: the override is read by `EntitlementStore` and honoured by `EntitlementPolicy` only under `#if DEBUG`; `setDebugOverride` does not exist in Release.
