# Cinemax - Jellyfin Client for Apple Platforms

Native Jellyfin client for iOS 26+ and tvOS 26+. "Cinema Glass" design system (dark glassmorphism, editorial layouts, no borders). SwiftUI multi-platform, single Xcode project (iOS + tvOS targets). Swift 6 strict concurrency.

**RULE — the product is called JellyGlass (display name, App Store, Jellyfin `Client` header) since 2026-09-22; the CODE keeps `Cinemax`, and must.** `CFBundleDisplayName` (set on all 4 targets in `project.yml`) carries the new name; `PRODUCT_NAME`, modules (`Cinemax`, `CinemaxKit`), bundle ids, targets, schemes, the `cinemax://` scheme, and the widget `kind:`s (renaming one wipes every widget already placed) stay as they are. The pre-auth wordmark is TEXT (`login.header` / `server.header`, in capitals) — search `grep -i`. Changing the `Client` header logs nobody out (Jellyfin never compares it).

> This file = the cross-cutting rules, gotchas and non-derivable context; each feature's own rules live in the area files listed below. Feature *behavior* is derivable from the code — read the owning file. Lines tagged **RULE** override default behavior.

## Architecture

- **CinemaxKit** local Swift Package at `Packages/CinemaxKit` — networking, models, persistence.
- `@Observable` + `@MainActor` for all state. `JellyfinClient` lives in ONE `nonisolated(unsafe)` state struct behind an `NSLock` (`JellyfinAPIClient.ClientState`, see `Packages/CinemaxKit/CLAUDE.md`). `import JellyfinAPI` plainly — never `@preconcurrency` (SDK 3.1 declares its DTOs `Sendable`; the annotation only hid diagnostics — removed from every file in audit lot 7).
- **RULE — iOS `NavigationStack`**: destinations pushed via `navigationDestination(item:)` render in a separate context — `@Observable` changes won't re-render unless the destination is a standalone `View` struct with its own `@Environment` properties, not an extension method returning `some View`.
- **RULE — Lazy-container navigation**: SwiftUI silently ignores `navigationDestination(item:)` inside `LazyVGrid/LazyVStack/LazyHStack/List`. Hoist the modifier to a non-lazy ancestor; bubble the action up via a callback that mutates a screen-level `@State`. Reference: `AdminItemMenu.onSelectDestination` → screen-level `@State AdminMenuPushIntent?`. Used by `MovieLibraryScreen`, `MediaDetailScreen`.
- **RULE — never nest a large `LazyVGrid`/`LazyHStack` inside a `LazyVStack`; the outer stack must be a plain `VStack`.** A lazy container's job is to defer the *hundreds* of children; a wrapper holding a header, one content branch and a `Spacer` has nothing to defer, and stacking two lazy containers over a big collection makes the screen's subgraph stop rebuilding entirely after the tab's `UIHostingController` is re-hosted. Symptom, measured on device 2026-08-20 on `MovieLibraryScreen.filteredView`: Films → « Non vus uniquement » → ~9 flicks of scrolling (≈4 paginated pages) → Accueil → Films rendered a **fully black tab** — no count header, no cards, no empty state, no skeleton, no error — and **no recovery**: a second tab round-trip, scrolling, pull-to-refresh and re-applying the filter all failed; only relaunching the app restored it. Reproduced 3/3 above that scroll threshold and 0/2 below it, which is what makes it look like a data bug and is why it long escaped notice — the data is fine throughout (the sheet still reads the filter, a refresh still issues its requests), it is the *view* that stops updating, which is why even the unconditional header disappears. **A blank screen whose unconditional chrome is also missing is a rendering failure, never a data failure** — look at the container nesting, not the view model.
- **RULE — never `ForEach` over an index snapshot while subscripting the live collection**: `data: Array(vm.items.indices)` + `{ idx in card(vm.items[idx]) }` crashes with `Fatal error: Index out of range` the moment the collection shrinks. Observation invalidates the already-instantiated `LazyHStack`/`LazyVStack` children **directly**, so they re-run their body against the emptied array *before* the ancestor's `!items.isEmpty` guard gets a chance to remove the row. Always pass the elements themselves + a stable `id:` keypath. Reference: `HomeScreen.watchingNowRow` — `HomeViewModel.reload()` sets `activeSessions = []` as its first statement, so every pull-to-refresh with the "En direct" row on screen crashed. Applies to any `@Observable` collection rendered through `ContentRow`.
- **RULE — Singleton root stores** (`AppNavigation.swift`; the `AppState` class itself lives in `AppState.swift`): `AppState`, `NetworkMonitor`, `MenuConfigStore` are `private static let` process singletons assigned into `@State` — scene-event struct recreation could otherwise redo main-thread disk work. `ThemeManager`/`ToastCenter` are NOT in this set.
- **RULE — Hand-built URLs must preserve the server base path** (`URLComponents+ServerPath.swift`): assigning `components.path` directly REPLACES the whole path, silently dropping the sub-path of sub-path-hosted servers (`https://host/jellyfin`) — every hand-built URL 404s while SDK-routed calls keep working. Always route through `setEndpointPath(_:preservingBasePathOf:)`. Applies to all hand-built endpoints (playback direct-stream, every `ImageURLBuilder` URL, SyncPlay REST/socket); Widget + Top Shelf carry a local copy (can't link CinemaxKit).
### iOS 26 / tvOS 26 API rules (all RULE)

- **`UIButton`**: use `UIButton.Configuration`; never `UIButton(type:)` + `setTitle/titleLabel?.font/backgroundColor/contentEdgeInsets`. Pattern in `NativeVideoPresenter`. Frosted bg via `config.background.customView = UIVisualEffectView(...)`.
- Free SwiftUI helpers returning `some View` that touch `PrimitiveButtonStyle.plain`/`Font`/etc. must be `@MainActor`.
- **iPad**: `UIRequiresFullScreen` removed (deprecated); split view / Stage Manager supported. Hero/backdrop heights are clamped to a viewport fraction via `containerRelativeFrame(.vertical) { min(fixedHeight, length * 0.55…0.62) }` (iOS only — tvOS keeps fixed heights) in `HomeScreen.heroSection` / `LibraryHeroSection` / `MediaDetailScreen.backdropSection` so short windows keep content below the hero reachable. New full-bleed heroes must follow the same pattern.
- **Toolbar + Liquid Glass**: iOS 26 auto-renders `ToolbarItem` buttons with Liquid Glass. **Never** add `.buttonStyle(.glass)`/`.glassProminent` on toolbar items (nests double capsules). Active state via `.tint(themeManager.accent)` + `.fill` icon variant.
### Dependencies

`jellyfin-sdk-swift` **v3.1.0** (was 0.6.0 until 2026-09-08; 3.0.0 is the **12.0 generation**, produced by openapi-generator since 1.0.0 — four things that generator changes for us: **memberwise inits order their parameters ALPHABETICALLY** (`TranscodingProfile(protocol:audioCodec:…)`, `ClientCapabilitiesDto(isSupportsMediaControl:…)` — a call site in schema order fails with "argument X must precede Y"); request-body types are named after the schema, not the endpoint (`PlaybackStateInfo` for start AND progress, `PlaybackQueueStateInfo` for Ready AND Buffering, `MetadataLookupInfo` for movie AND series identify, `NameIDPair`); **fields the 12.0 spec marks required decode STRICTLY** — `UserItemDataDto.key`, `UserPolicy.authenticationProviderID`/`passwordResetProviderID` — so test fixtures need `UserItemDataDto(key:)` and a server that omitted them would fail the whole DTO; and routes hidden from the spec are simply absent — `Paths.stopEncodingProcess` is gone, see the `stopEncodingRequest` note under Video Playback. It pulls `swift-nio` + `swift-nio-transport-services` (its own socket, which we do not use — ours is `JellyfinSocket`) and a **binary `openapi-generator` artifact** from LePips's GitHub releases: a stale `~/Library/Caches/org.swift.swiftpm/artifacts/https___github_com_LePips_openapi_generator_*` dir fails resolution with `already exists in file system` — delete it; CLI builds need `-skipPackagePluginValidation`, which `ci.yml` already passes. The SDK also exports `JellyfinSocket`, `Session`, `Subscription`, `QuickConnect` — no collision with ours, since CinemaxKit's own declarations win inside the package and no `Shared/` file naming them imports `JellyfinAPI`; keep it that way. Its `QuickConnect` helper and socket are deliberately NOT adopted — ours carry the one-socket-per-session and poll-failure-budget rules), `Nuke`/`NukeUI` v13.2.0, `AVKit`/`AVPlayer`, `SwiftVLC` (libVLC 4.0, Swift 6 — [harflabs/SwiftVLC](https://github.com/harflabs/SwiftVLC), pinned **exactVersion 1.0.0**; needs swift-tools 6.3 / Xcode 26.4+, local toolchain is Xcode 27.0 / Swift 6.4 since 2026-09-15. Every 0.3.0→1.0.0 tag embeds the **same libVLC 4.0.6**; 1.0.0's win is an assert-free core (≈860→348 `__assert_rtn` refs in the tvOS `.a`) — upgraded as the candidate fix for the A15 4K stutter. 1.0.0 mutators **throw** (`setAudioDelay`/`setSubtitleDelay`/`setPlaybackRate(PlaybackRate)`/`seek(to:)` — `rate`/`audioDelay`/`subtitleDelay` are get-only now); `PiPVideoView(managesAudioSession:)` defaults **true** — `PlayerEngineSurface` passes `false`, see the `PlaybackAudioSession` RULE; `PiPController.isPossible`/`isActive` removed).

- `import SwiftVLC` works iOS + tvOS (`Player` is `@Observable @MainActor`; `VideoView`/iOS-only `PiPVideoView` are SwiftUI representables hosted in UIKit presenters via a child `UIHostingController`). Both `Cinemax` (iOS) and `CinemaxTV` (tvOS) targets link it — VLC is the default online playback engine on both.
- **RULE — Never re-add `VLCKitSPM`** — libVLC 3.x + 4.0 in one binary collide on `libvlc_*` C symbols. SwiftVLC replaced it (native PiP, object-based `Track` API fixing the audio-switch silence bug, Swift-6-native).
- **Dependency audit** (`scripts/dependency-audit.py`, CI job *Dependency audit* — plain Python on Linux, no toolchain install): `check` fails when the app's `Package.resolved` moves a pin not recorded in `docs/dependencies/checksums.md`, when `Packages/CinemaxKit/Package.resolved` disagrees with it, when a `LicensesView` version disagrees with its pin, when a resolved package is not credited in `LicensesView` (transitive ones included) or a credited one is no longer resolved, or when a pinned manifest's `.binaryTarget` checksum (SwiftVLC's `libvlc`, the SDK's `openapi-generator`) differs from the recorded one; `sbom` writes a CycloneDX 1.5 JSON, uploaded as the `cinemax-sbom` artifact on `main`. **RULE — a dependency moves in ONE PR together with its recorded pin, its `LicensesView` version and (for a binary artifact) its checksum.** SwiftPM already verifies each downloaded archive against the checksum its own manifest declares; what nothing verified is that a revision was *reviewed*, which is what the recorded list adds. Dependabot (`.github/dependabot.yml`) watches `Packages/CinemaxKit` weekly plus GitHub Actions; it cannot read the Xcode project, so its PRs fail `check` ("sync") until the app's `Package.resolved` is re-resolved in Xcode — by design. SwiftVLC is ignored there (pinned `exactVersion` on purpose; Dependabot names it `github.com/harflabs/swiftvlc`). `check --offline` skips the manifest fetches for a quick local run.
- **RULE — Adding a new file under `Shared/` requires re-running `xcodegen generate`** before it builds (the PostToolUse hook auto-regens only on `project.yml` edits, not new files; symptom of forgetting: "cannot find type X in scope" for a type that exists) Remote/Linux sessions (Claude Code on the web) have no xcodegen — CI still passes because it regenerates the project itself, but the committed `project.pbxproj` goes stale and local builds break; the CI "Verify committed project.pbxproj" step fails the PR until someone runs `xcodegen generate` on a Mac and commits the result. xcodegen is **version-pinned** in `ci.yml`/`regen-project.yml` (`XCODEGEN_VERSION`, official release zip — never `brew install`: heterogeneous runner brew caches made the verify step a per-runner coin flip when a formula bump changed the output format); bump the pin, the local install, and the committed pbxproj together.)
- **RULE — `@Observable` properties must NOT carry `didSet`/`willSet`**: the macro instruments setters via `withMutation { ... }`; a property observer body runs *after* the observation commits, and on collection-of-`Codable`-value-types properties (e.g. `[MenuEntry]`) the combo intermittently fails to deliver SwiftUI re-renders (symptom: bottom tab bar doesn't update after a reorder until the user taps anywhere). Pattern: keep stored properties plain `var T`, expose explicit `set*(_:)` mutator methods that mutate + persist, and use custom `Binding(get:set:)` in Pickers/Toggles so writes go through the mutator. Reference: `MenuConfigStore.setMode`/`setCustomKind` and the `Binding` projections in `MenuSettingsScreen+iOS.swift`.
### Swift 6 `nonisolated` escape hatches (safe when body only reads parameters)

1. `View, Equatable` sub-type inside a `@MainActor` screen needs `nonisolated static func ==` (`Equatable` isn't main-actor-isolated). See `PlayActionButtonsSection` in `MediaDetailScreen.swift`.
2. A `@MainActor` class's `static func` returning non-Sendable into a `TaskGroup @Sendable` closure needs `nonisolated private static func`. See `HomeViewModel.fetchGenreItems`.
3. A `nonisolated static func` reading a `static let` needs the constant `nonisolated` too (Sendable types only). See `SearchViewModel.sanitize` + `maxQueryLength`.
4. When `nonisolated static func ==` reads a non-Sendable DTO stored property, wrap the body in `MainActor.assumeIsolated { ... }` (safe — SwiftUI diffs on main actor). See the `MediaDetail*Section` / `MediaDetailEpisodeCard/Row` extractions.
5. **`@retroactive @unchecked Sendable` for SDK value enums — no longer needed, and re-adding one is now an ERROR.** SDK 0.6.0 shipped `BaseItemKind` (a `String`-raw enum) without `Sendable`, and `@preconcurrency import` didn't satisfy Swift 6.1's region-based isolation, so `Packages/CinemaxKit/.../Models/JellyfinSendable.swift` bridged it. **SDK 3.1.0 declares those conformances itself**, which makes the retroactive one a hard build error ("Conformance of 'BaseItemKind' to protocol 'Sendable' was already stated in the type's module 'JellyfinAPI'") — the file was deleted 2026-09-10. If a future SDK type genuinely lacks it, re-create the bridge file and keep the conformances strictly scoped to safe value types (String-raw enum, no associated values); check the SDK first.
6. **Swift 6.4 `#ImplicitStrongCapture`** — an inner `[weak x]` whose enclosing closure captures `x` IMPLICITLY (a bare `Task { … }` in a class, a SwiftUI `.task { … }` reading a property) warns that the weak capture is ineffective, the outer closure already holding `x` strongly. Make the OUTER capture explicit (`Task { [self] in`, `Task { [weak self, avPlayer] in`) — the lifetime was already that, so nothing changes at runtime — or drop the `weak` when both ends are process singletons (`AppNavigation`'s `isOnlineProvider`). References: `VideoPlayerCoordinator.play`, `NativeVideoPresenter.present` / `navigateToEpisode`.

## Localization

- `LocalizationManager` (`@Observable`, injected from `AppNavigation`). Default `fr`, also `en`.
- **RULE — a count goes through `loc.counted(key, n)` (or `loc.pluralKey` when the string has more arguments), backed by a `<key>.one` sibling, never `n == 1 ? … : …`** (audit 2026-09-22). No `.stringsdict`: a new resource file needs an `xcodegen` run. The ONE rule is `LocalizationManager.usesSingular` — French puts 0 AND 1 in the singular (« 0 film »), English only 1 — which the old hand-rolled `== 1` tests got wrong in French, alongside the keys with no singular at all (« 1 films », « 1 titres », « et 1 autres », « %dm restantes »). A new `counted` key needs its `.one` in BOTH tables; `PluralRuleTests` lists them.
- **RULE — dates, relative times and decimals are formatted in the APP's language: `loc.locale` (the app language + the device's region), injected at the root as SwiftUI's `\.locale` and passed to every `FormatStyle` the app builds** (`.locale(loc.locale)`, `loc.decimal(_:)` for ratings, `AdminRelativeFormatter.string(for:style:locale:)`; audit 2026-09-22, Q7). They followed the DEVICE language: « Sep 22 » and « 7.5 » inside a French app. The admin screens' five `nonisolated(unsafe) static let RelativeDateTimeFormatter`s went with it — `Date.RelativeFormatStyle` is a `Sendable` value carrying its locale. Never `String(format: "%.1f")` for a user-visible number, never a bare `.formatted()` on a date.
- **RULE — All strings via `loc.localized("key")` / `loc.localized("key", args...)` — never hardcoded.** Strings at `Resources/{lang}.lproj/Localizable.strings`. Reactivity: `@ObservationIgnored` + `@AppStorage` + `_revision`. Use plural helpers (e.g. `remainingTime(minutes:)`), not inline branching.
- **RULE — never surface raw `error.localizedDescription` to users** (leaks cryptic SDK strings like `unacceptableStatusCode(401)`). Map via `LocalizationManager.userFacingMessage(for:)` (→ network / session-expired / generic localized text); log the raw error instead. VMs that show errors take `loc:` and `logger`.
- **RULE — the app language rides every API request as `Accept-Language`, through `ServerAPI.setPreferredLanguage(_:)` — one owner, `AppNavigation` (set BEFORE `restoreSession` builds the client, then `onChange(of: loc.languageCode)`); the headless intent client reads the same `appLanguage` default.** Jellyfin 12.0 localizes per request from it (jellyfin PR #16488): the media-stream `DisplayTitle`s become « Par défaut » / « Forcé » instead of « Default » / « Forced », plus activity strings. **Deliberately NOT gated on `ServerVersion`**: 10.x has no request-localization middleware and ignores the header, so it is the one 12.0 feature that is harmless everywhere — and gating it would make the version probe a prerequisite for a header that costs nothing. The header lives in the `URLSessionConfiguration` (the SDK client offers no per-request hook) — **and the raw PlaybackInfo POST, which runs on its own `playbackInfoSession`, re-attaches it by hand (`applyAcceptLanguage`)**: that response is where the stream `DisplayTitle`s the pickers print come from, so the SDK-side header alone would have localized everything except the one thing the user sees. A change rebuilds the client **in place** (same server, same token — `_accessToken` is kept for exactly this — and the learned `ServerVersion` survives, unlike `reconnect`) and drops `APICache`, whose keys carry no language. View ids are stable across languages on 12.0 (jellyfin PR #17714); on 10.x the header is never read, so the per-server `MenuProfile` cannot drift. Mapping is `acceptLanguageHeader(for:)` (`fr` → `fr-FR, fr;q=0.9`), locked by `AcceptLanguageTests`.
- **RULE — never print `BaseItemKind.rawValue` to the user**: it is the wire enum (« Movie » / « Series » in English whatever the app language) — go through `loc.itemKind(_:)` (`item.kind.*` keys; a kind with no label returns `nil` and is left out, never printed raw). **`loc.decimal(_:)` formats with the app LANGUAGE alone, not `loc.locale`**: with the device's region attached, a French app on a US-region phone (`fr_US`) still printed « 5.9 » (recette 2026-09-23); dates keep `loc.locale`, where the region decides day/month order. Locked by `CardLabelLocalizationTests`. An admin text FIELD that is parsed back (`MetadataEditorScreen`'s rating) deliberately keeps the point.
- **RULE — Info.plist permission usage-descriptions are localized via `Resources/{fr,en}.lproj/InfoPlist.strings`, NOT `loc.localized`**: the system reads them before any Swift runs. Base English lives in `project.yml` per target; `InfoPlist.strings` overrides per language (keys `NSLocalNetworkUsageDescription` / `NSMicrophoneUsageDescription` / `NSSpeechRecognitionUsageDescription` — tvOS carries only the first). Both files are auto-bundled because the app targets already list `Resources` as a source path. Keep fr the natural default. Any new `NS*UsageDescription` must be added to both `InfoPlist.strings` files too.
## Build

```bash
# iOS
xcodebuild build -project Cinemax.xcodeproj -scheme Cinemax -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
# tvOS
xcodebuild build -project Cinemax.xcodeproj -scheme CinemaxTV -destination 'platform=tvOS Simulator,name=Apple TV 4K (3rd generation)'
# Regenerate Xcode project
cd Cinemax && xcodegen generate
```

**Build verification gotchas (RULE)**:
- Always pair pipes with `set -o pipefail` (`set -o pipefail; xcodebuild ... | grep ...`) — without it `tail`/`grep` swallow xcodebuild's exit code and a failed build returns 0. Confirm by reading output for `** BUILD SUCCEEDED **` / `** BUILD FAILED **`, not just shell exit.
- **CI's *Build & Test* job gates every step on a docs-only check** (`Detect code changes`): a PR touching only `*.md` / `docs/` still gets a green job, with nothing built — never read that green as a build. It also pins Xcode — **27.0, on GitHub's `xcode-27` image** (`runs-on` + `Select Xcode`, keep both in step with `xcodeVersion` in `project.yml`; a version missing from the image FAILS the job rather than falling back to the image default; that image has no « iPhone 17 Pro » simulator, so CI tests on « iPhone 17 ») and compiles both apps in **Release** after the tests, the only place `#if DEBUG` branches and the optimiser are seen before archiving.
- **CI checks FR/EN parity** (`scripts/check-localization-parity.py`, in the *Dependency audit* job): a key in one language only, a `.one` without its base key, or format specifiers that differ between the two languages fail the PR. The pre-commit hook refuses to regenerate the project with an xcodegen other than the pinned `XCODEGEN_VERSION`.
- **RULE — the SwiftLint job BLOCKS**: SwiftLint is pinned (`SWIFTLINT_VERSION` + SHA-256 in `ci.yml`, release zip, never `brew`) and runs `--strict` against `.swiftlint-baseline.json`, which holds every violation older than the job going strict (audit lot 7). A new violation fails the PR — fix it, don't re-baseline. When you FIX a baselined violation, regenerate the baseline in the same commit: entries match on file + rule + line text (many with empty text), so a stale entry can absorb an identical new violation. The baseline's paths are RELATIVE to the repo root; SwiftLint writes them absolute when run from a symlinked path (`/tmp` → `/private/tmp`), so regenerate it from a real checkout path, with the pinned version.
- Don't run iOS + tvOS builds in parallel against the same DerivedData — they race on `build.db` ("database is locked"). Run serially.
- **RULE — `ci.yml`'s concurrency group is PER COMMIT on main (`…-${{ github.sha }}`) and per ref everywhere else, and `cancel-in-progress` is false on main.** A shared group on main cancels main's OWN verification, and dropping `cancel-in-progress` is NOT enough on its own: GitHub keeps at most one *pending* run per group (`queue: single`, the default) and cancels the previously pending one, so a burst of 3+ merges still loses every intermediate commit. That is how `ea96635` came to sit on main with a genuinely stale `project.pbxproj` and turned **four unrelated Dependabot PRs red** on a fault none of them had introduced — the failure surfaces on the PRs, never on the commit that caused it, which is what makes it expensive to diagnose. Corollary for reading CI at all: **a green PR run is not proof for a step gated `push && ref == main`** — the *Upload SBOM* step, i.e. the only thing exercising `actions/upload-artifact`, is skipped in every PR run, so an upload-artifact bump is verified by reading that step's own conclusion on main plus the `cinemax-sbom` artifact's existence, not by the run's colour.

**RULE — a test never writes `UserDefaults.standard` for a key a view model reads; it passes `UserDefaults.isolatedForTesting()`** (`MockAPIClient.swift`) through the view model's `defaults:` seam. Suites run in parallel, and `HomeRailGatingTests` switching rails off in `.standard` leaked into every `HomeViewModelTests` load running at that moment (audit 2026-09-22, T2). **A test never SLEEPS to let async work land** (audit T3): it awaits the work itself (`PlaybackReporter.drain()`, a view model's exposed task — `SearchViewModel.searchTask`, `LoginViewModel.quickConnectTask`), holds a race open with a `TestLatch`, or, with no seam, polls through the bounded `eventually { … }` (both in `MockAPIClient.swift`). A fixed sleep stays only where the test measures elapsed time (a TTL, a deadline) or models latency inside a mock. Likewise a test touching a REAL Keychain item restores it (`sharedSessionRoundTrips` puts the widget's live session back — the test host is the app, T4). **A new test file needs an `xcodegen` run** (the pbxproj lists each file), so remote/Linux sessions append suites to an existing file instead — the device-profile suite (`DeviceProfileTests`: no `mpeg4`, `ts` segments, `minSegments: 1`, no `mp1/mp2/mp3` in the transcode list, `isSeekHeavyContainer`; the builders are `internal` for it) lives in `AuthedURLTests.swift` for that reason.

**Tests**: unit tests (swift-testing) live in `Tests/CinemaxKitTests/` but the Xcode target/product is **`CinemaxTests`** (in-app bundle, `TEST_HOST = Cinemax.app`, `@testable import Cinemax`). Run via `xcodebuild test -scheme Cinemax ...`. **RULE — `-only-testing` silently runs 0 swift-testing tests** — run the full suite and grep for `Suite "Name"` / `✔`. **RULE — never add `package: CinemaxKit` to `CinemaxTests` (or `CinemaxTVTests`) in `project.yml`** (double-links the `Get` dependency → linker errors; the app target already carries it).

**tvOS tests**: the SAME sources also build as **`CinemaxTVTests`** (`TEST_HOST = CinemaxTV.app`, attached to the `CinemaxTV` scheme): `xcodebuild test -scheme CinemaxTV -destination 'platform=tvOS Simulator,name=Apple TV 4K (3rd generation)' -skipPackagePluginValidation`. CI runs it after the iOS suite, serially (shared DerivedData). **RULE — the tvOS app's module is `CinemaxTV`, and the bundle carries `-module-alias Cinemax=CinemaxTV`**, so every `@testable import Cinemax` resolves to the tvOS app there — never rename the app module or rewrite imports per platform. **RULE — a test that touches an iOS-only type (Admin, Intents entities, `ResumeControlIntent`, …) is wrapped in `#if os(iOS)`**, or the tvOS bundle stops compiling; tvOS-only assertions go under `#if os(tvOS)` (`TVLayoutMetricsTests`). Both CI steps grep the raw log for swift-testing's `✔ Test run with N tests` line (N > 0) and one platform-only suite (`Identify applies the chosen artwork` / `tvOS layout metrics`), because an xcodebuild exit code alone cannot tell "passed" from "ran nothing".

**Versioning**: `iOS/Info.plist` + `tvOS/Info.plist` use `$(MARKETING_VERSION)`/`$(CURRENT_PROJECT_VERSION)` — `project.yml` `settings.base` is SSOT. Bump `MARKETING_VERSION` per user-visible release; `CURRENT_PROJECT_VERSION` per archive/upload.
## Claude Code automations (`.claude/`)

Project-shared, checked into git. Per-developer overrides in `.claude/settings.local.json` (gitignored).

- **Git pre-commit hook** (`scripts/git-hooks/pre-commit`, versioned; enable once per clone with `git config core.hooksPath scripts/git-hooks`): when `project.pbxproj` is **staged**, it regenerates a pristine XcodeGen output into the **index only** and restores your working copy. Building to a physical device requires `DEVELOPMENT_TEAM`, which Xcode writes into the project (it also rewrites settings into equivalent-but-different syntax, e.g. `OTHER_LDFLAGS` as an array), and CI's "Verify committed project.pbxproj" step rejects all of it. So the team id stays local, the commit stays pristine. **Consequence by design: `project.pbxproj` normally shows as modified in `git status` — that is the local churn, and committing it is exactly what the hook prevents.** Falls back to stripping only `DEVELOPMENT_TEAM` from the staged blob where XcodeGen isn't installed (Linux / remote sessions), which cannot undo syntax rewrites.
- **Hooks** (`.claude/settings.json`): `PreToolUse` blocks edits to `Cinemax.xcodeproj/project.pbxproj` (XcodeGen output — edit `project.yml`). `PostToolUse` auto-runs `xcodegen generate` after `project.yml` edits. `PreToolUse` on Bash matching `gh pr create` injects a **CLAUDE.md freshness gate** — review the branch diff and update the rules file of each AREA the diff touches (see *Where the rules live*), not this root file, BEFORE creating the PR; the gate also flags a root `CLAUDE.md` above 45 KB.
- **Skills**: `localize-check` (FR/EN `Localizable.strings` key parity + hardcoded-string grep), `design-system-review` (`conventions.md` checklist grep sweep on staged files).
- **Subagents**: `tvos-focus-reviewer`, `swift6-concurrency-reviewer`, `jellyfin-api-reviewer` (each told which area files to read).
- **MCP servers** (`~/.claude.json` project scope): `context7` (live docs), `github` (token from `gh auth token`).
