# Audit plateforme post SDK 3.1.0 / Jellyfin 12.0 — 2026-09-10

Contexte : SDK jellyfin-sdk-swift 0.6.0 → 3.1.0 (génération 12.0), serveur de référence 10.10 → 10.11 → 12.0. Exigence dure : rétrocompatibilité Jellyfin 10.x. Trois audits en lecture seule (surface API, code mort, performance), sur `main` à `6886654` (PR #153 mergée). Chaque item vérifié dans le source avant inscription ici.

## 1. Compatibilité 10.x — verdict

**Aucune régression 10.x introduite par le lot 12.0.** Aucun appel 12-only sans garde `ServerVersion`.

**Le plancher réel est 10.9, pas 10.8** — et ce depuis le SDK 0.6.0 (spec 10.11), pas depuis 3.1.0. Le SDK ne génère plus les routes `/Users/{userId}/…` ; l'app dépend de `/UserItems/Resume`, `/Items/Latest`, `/UserViews`, `/UserPlayedItems`, `/UserFavoriteItems`, `/Users/Password`, `/Users/Configuration` (toutes 10.9+), y compris dans le Widget et le Top Shelf. Revenir à 10.8 = reconstruire ~10 routes à la main. **À acter dans CLAUDE.md.**

### Refactors plus larges (mesure préalable)

- **R1 — le plus gros payload de l'app** : les cartes de navigation d'Accueil appellent `getEpisodes` (`fields: [.overview, .mediaSources]` + userData) pour ≤ 40 saisons alors que seuls `id`+`name` servent (`PlayLink.swift:44-55`). Ordre de grandeur 0,5–4 Mo de JSON par chargement d'Accueil et à chaque tier-1 / pull-to-refresh. Fix : `LibraryAPI.getEpisodeRefs` (`fields: []`, sans userData/images, TTL 300 s hors `userDataCachePrefixes`), consommé par Home, `fillMissingEpisodeNavigation`, `CardEpisodeNavigationResolver`. **Mesurer d'abord** : `curl` de `/Shows/{id}/Episodes` avec/sans `fields` sur le NAS.
- **R2** : `fields: [.overview, .genres, .childCount]` sur tous les `getItems` (`+Library.swift:177`) ; `overview` n'est lu que par deux héros. Paramètre `fields:` avec défaut inchangé, trimmé sur ~10 sites de rangées/grilles.
- **R3** : single-flight `coalesce` absent sur `getSeasons` / `getEpisodes` / `getNextUp` / `getGenres` (motif de `getItem :266-277`) ; chevauchement réel entre le fan-out Home et `CardEpisodeNavigationResolver.probe`.
- **R4** : fiche d'un épisode = 3 sauts séquentiels (`getItem(ép)` → `getItem(série)` → seasons/nextUp/similar) ; `async let` sur le second gagne une latence réseau.
- **R5** : `ThemeManager.accent` alloue un `Color.dynamic` par lecture (275 sites, dont `cinemaFocus()` par carte) — cacher 4 `Color` invalidées par `_accentRevision` ; **Time Profiler avant de conclure**.
- **R6** : `getUserViews` non caché (bibliothèque tier-1 + menu) ; `LocalizationManager.localized` sans mémo (gain probablement faible).

Vérifié et non retenu : formatters (hoistés), `AnyView` (0), boucles de poll (toutes annulées à la disparition — une réserve : vérifier que tvOS livre `onDisappear` au changement d'onglet, sinon le poll 20 s continue sur un Accueil caché), 5 `getItem` du démarrage lecture (single-flight OK), proxy (tampons/backpressure OK).
