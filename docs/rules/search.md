## SearchScreen

`SearchViewModel.search(using:)` debounces 400ms → `LibrarySearchRanker.rank(...)`. Decomposition: shell + file-private `VoiceSearchButton` (iOS), `SearchResultsGrid`, `SearchResultCard`. iOS mic → `SpeechRecognitionHelper`. **Surprise Me**: `fetchRandomMovie`/`fetchRandomSeries` are separate methods (Swift 6 flags `[BaseItemKind]` built from a parameter as non-Sendable crossing the API actor; literal arrays work).

- **Type filter chips (All / Movies / Series)**: `SearchScope` enum → `viewModel.scope`; shown once a search is under way. `LibrarySearchRanker.rank` takes an additive `includeItemTypes: [BaseItemKind]` param threaded into `searchItems` (default `[.movie, .series, .episode]` in the `LibraryAPI` extension so existing callers are unchanged). Changing a chip re-runs the current query (`search(using:)`). tvOS chips use `TVFilterChipButtonStyle`; iOS uses the accent-capsule idiom. Keys `search.filter.{all,movies,series}`.
- **Poster context menus** (`SearchResultCard`): shared `.mediaCardContextMenu(item:)` — long-press / long-press-select watched + favorite toggle (see Media Library RULE).
- **Person row** (`SearchPersonRow`, file-private in `SearchScreen.swift`): round portraits (`CastCircle`) above the poster grid, pushing to `PersonDetailScreen`. Fed by `LibrarySearchRanker.rankPersons` → `LibraryAPI.searchPersons` → `GET /Persons`. **RULE — `/Persons`, never `/Search/Hints`**: the former returns a `BaseItemDtoQueryResult`, i.e. `BaseItemDto` like the rest of the pipeline (scoring, `ImageURLBuilder` and `PersonDetailScreen` all apply unchanged); `/Search/Hints` returns a separate `SearchHint` model and would fork the search pipeline into two result shapes for no gain. **One server call**, not `rank`'s per-word fan-out: Jellyfin's contiguous `searchTerm` breaks punctuated titles ("Mission : Impossible") but not person names, where the server's `contains` already finds "Cillian Murphy" from "murphy" — the local score only orders the row. Limits: `personFetchLimit` 30 (server), `personRowLimit` 10 (row). **RULE — the row renders only in `.all` scope AND only when non-empty**: a type filter that surfaces something other than the requested type isn't a filter (narrowed scopes don't even spend the request), and a "People" heading over nothing is a visual bug. **RULE — the empty/`no results` branches gate on BOTH `results` and `personResults` being empty**, and the "Top matches" heading is itself conditional on `!results.isEmpty` — an actor name matching no title is the row's *primary* use case, and testing `results.isEmpty` alone routed it straight to "Aucun résultat" with the row never drawn. **RULE — a failing `searchPersons` touches neither `results` nor `searchFailed`**: `rankPersons` swallows its error into an empty array, so the degraded mode is an absent row; the retryable error screen stays owned by the title search alone. Hand-rolled rather than reusing `ContentRow` — historically that component hardcoded `spacing6` horizontal padding (it now takes `CinemaTVLayout.pagePadding` on tvOS, so the reason is gone on tvOS but the row was left as is). Persons carry no rating, so the row can surface an actor whose every film is hidden by `privacy.maxContentAge` — nothing is revealed, and `PersonDetailScreen` goes through the already-capped `getPersonItems`. Key `search.people`.

### Seerr section « Pas encore dans ta bibliothèque » (Pro « Demandes », lot 1b)

The search screen is the first browse surface of Seerr (`Shared/Seerr/CLAUDE.md` holds the Seerr-wide rules). `SearchViewModel.seerrSection` (`MissingSection<SeerrMissingTitle>`), loaded in the SAME `searchTask` as the library, after it; `SearchScreen` wires `viewModel.seerr` and `allowsSeerr` (`seerr.isVisible(proAllows:isOnline:)`, the `HomeScreen.allowsElsewhere` pattern) in its `.task`, before the first query.

- **RULE — the section comes AFTER the library results, never above, and also shows when there are none.** It is the last child of `SearchResultsGrid`, after the person row and the poster grid; nothing the library owns moves when Seerr answers. `isSearching` is cleared BEFORE the Seerr phase — it replaces the whole grid, so a section loaded under it would never show its skeleton. The skeleton (`.loading`) is written only once the library results are, and only when `allowsSeerr()` held both before the fetch (that is what asks `searchItems` for `ProviderIds`) and after it.
- **RULE — silent on failure.** An error or `loadSection`'s deadline ⇒ `.hidden`: no message, no banner, no « Seerr » word (`seerr.request.seasonsUnavailable` for a failed series lookup says « saisons », never the tool). A `nil` from `loadSection` (the account moved) writes `.hidden` too — unless the task was cancelled, in which case the newer search owns the state — or the skeleton would wait for the next profile's Seerr to become visible.
- **RULE — re-read at render, per account.** The grid receives `viewModel.seerrSection(for: seerr.snapshot())` behind `seerr.isVisible(…)`: the section is drawn only for the account and generation it was loaded for, so another profile never sees it, even once its own Seerr is connected (same server ⇒ the tab is not rebuilt on a switch).
- **RULE — the empty-state branches are unchanged where Seerr does not apply.** With a Seerr part to follow (`seerr.isVisible` or the invitation, i.e. decided by the GATES, not by the section's state, so the empty state does not jump when Seerr answers), « Aucun résultat » is drawn at the top of the grid (scrollable) with the section or the invitation below it; otherwise the centred `EmptyStateView` of before.
- **RULE — `SearchResultsGrid ==` covers every Seerr property** (`noResultsTitle`, `seerrSection`, `missingTitle`, `missingCardWidth`, `showsSeerrPrompt`, `isSigningInToSeerr`) — behind `.equatable()` a property left out never re-renders. The card's BADGE is not a grid property: `SearchMissingCard` reads `SeerrRequestPresenter` itself, so it flips after a request without the grid comparing unequal.
- **RULE — the grid's outer stack is a plain `VStack`** (root lazy-container RULE): it holds the person row, the poster grid and the Seerr row — three lazy containers it must not nest in a `LazyVStack`.
- The section follows the scope chips (`SearchScope.seerrKinds`: all ⇒ films + series, Films ⇒ films, Séries ⇒ series); people and collections are dropped by the decoder. Ownership is kind-keyed (`SeerrMissing.ownedTmdbIds` over the library results). A card tap goes through `SeerrRequestPresenter.request(_:session:loc:toasts:)`: a film opens the request at once, a series first loads `/tv/{id}` and offers every missing season, all ticked.
- **The invitation « Il te manque un titre ? »** — the ONE browse place allowed to name Seerr — replaces the section when `seerr.showsConnectPrompt(…)` and this account has not answered « Plus tard » (`SettingsKey.seerrSearchPromptDismissed(accountKey:)`, mirrored in a `@State` set for the session since the dynamic key is not observed). « Se connecter à Seerr » = `SeerrSession.signInToSavedAddress` (the Settings path: Quick Connect probed first), a failure toasts the connection test's title + fix; on success the query is searched again so the section fills. tvOS: its two buttons are one `.focusSection()` row.

### Permissive weighted search (`LibrarySearchRanker`)

**RULE — matching lives in `LibrarySearchRanker` (`Shared/ViewModels/`), never back inside a view model** — and nothing Seerr lives there: `rank(…, includeProviderIds:)` only passes the flag to `searchItems` (the intent query passes `false`); the missing-title logic is `SeerrMissing`'s. It is the SSOT shared by the search screen AND the App Intents entity query, and that sharing is load-bearing: it is what makes resolving a *spoken* title viable without a local index, since the normalization folds exactly what dictation drops (punctuation, diacritics). Two copies would drift and Siri would silently stop matching titles the screen still finds. Members: `sanitize` (input hygiene, applied to typed, dictated and Shortcuts-supplied terms alike), `normalize`, `significantWords`, `score`, `rank`.

Jellyfin's `searchTerm` is contiguous + punctuation-sensitive — "Mission Impossible" misses "Mission : Impossible". `rank` (pure, non-isolated, takes `any LibraryAPI` which is `Sendable`) fans out **concurrent** `searchItems` calls for the full phrase **AND each significant word** (`TaskGroup`), unions/dedups by id, then ranks locally. **Stop words** (FR/EN articles/conjunctions, `LibrarySearchRanker.stopWords`) are dropped from per-word fetches + scoring so "the"/"le"/"de" don't match everything. `score` tiers (score 0 ⇒ filtered out): **(1)** full normalized query is a contiguous run in title (+bonus exact / prefix) **(2)** every query word present but separated **(3)** only some words present (× fraction). Scored against `name` **and** `originalTitle` (max). `normalize` folds diacritics + lowercases + collapses any non-alphanumeric run to a single space.

### Voice search (`SpeechRecognitionHelper`, iOS only) — RULES

- **RULE — every off-main framework callback must be `@Sendable` (nonisolated).** TCC permission callbacks, the `AVAudioEngine` `installTap` block (audio render thread), and the `recognitionTask` result handler all fire off the main actor; a `@MainActor`-isolated closure there traps with `dispatch_assert_queue_fail` / `_swift_task_checkIsolatedSwift`. Fixing only the one in the stack trace leaves the others crashing identically. Permission requests bridge through `nonisolated static func ... async` + `withCheckedContinuation`; the tap captures the request via `nonisolated(unsafe) let` (its `append` is thread-safe); the result handler is `{ @Sendable [weak self] … }` (a `@MainActor` class IS `Sendable`, so weak-self capture is legal) that extracts Sendable values then hops via `Task { @MainActor }`.
- **RULE — empty-transcript guard**: forward a transcript only when non-empty. On `stop()`, `endAudio()` finalizes and can emit a final result with an EMPTY `formattedString`; propagating it wipes `searchText` (and the results) the instant the mic turns off.
- **Silence auto-stop**: buffer recognition never self-reports `isFinal`. A `silenceTimer` (Task) armed at start with a longer `initialTimeout` (5s — server recognition has first-result latency, a short timeout would kill the session before any word lands) then re-armed at `silenceTimeout` (1.5s) on every partial transcript; firing calls `stop()`. `stop()` is idempotent (guards on `audioEngine.isRunning || recognitionRequest != nil`) since it arrives from timer / final result / manual tap.
- **RULE — every bail-out must clear `isListening`, and `onPermissionError` is the single owner**: `toggleListening` flips the flag optimistically, *before* the TCC prompts resolve. All five helper bail-outs (speech denied, mic denied, recognizer unavailable, `setCategory`/`setActive` throwing, zero sample-rate input route) fire `onPermissionError` and return **without** reaching `stop()` — whose idempotency guard early-returns before `onStopped` anyway, since nothing ever started. So the reset lives in the `onPermissionError` wiring in `setupSpeechCallbacks`, not on the individual paths; a new bail-out must route through that callback or the mic pill keeps pulsing "listening" over a dead recorder.
- **Listening UI**: the trailing toolbar mic button expands into a Liquid-Glass pill (`mic.fill` + `search.listening`, pulsing via `symbolEffect(.pulse, isActive: motionEffects)`) while `isListening` — no separate label, no `.glass` style (iOS 26 auto-wraps toolbar buttons; an explicit capsule would nest).
- **RULE — the iOS idle state (nothing typed: invitation, recent searches, « surprise » pills) SCROLLS** (`idleContent` in a `ScrollView`, at least as tall as the viewport so it stays centred while it fits): with search history shown, German's stacked « surprise » pills went under the tab bar and nothing scrolled (recette 2026-10-08, M1-17).
